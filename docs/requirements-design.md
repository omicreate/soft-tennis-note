## 1. アプリ概要

ソフトテニスの試合をスマートフォンで記録し、試合中または試合後に次の行動へつなげるための記録・分析アプリ。

単なるスコア記録ではなく、以下を目的とする。

- 1ポイントごとの得点・失点理由を残す
- 自チームの得点パターン、ミス失点、相手ミスを分けて見る
- 試合中に短時間で確認できる注意点を出す
- 試合後に次に活かすポイントや次戦の狙いを整理する
- サマリー画像やCSVで振り返り・共有できるようにする

想定利用者は、保護者、控え選手、指導者、選手本人の振り返り利用。試合中にプレーしている選手本人が入力することは主想定ではない。

## 2. 基本方針

### 2.1 記録より活用を重視

データを取ること自体を目的にせず、記録したデータから次の行動を考えやすくする。

例:

- `ミス失点` が多いなら、まず失点を減らす
- `相手ミス得点` が多いなら、相手が崩れた配球を確認する
- `選手別 + / -` とプレー内容内訳で、誰が何で得点・ミスしたかを見る
- `最初の2本で失点` が多いなら、ゲーム序盤のまず返すを意識する

### 2.2 オフライン・端末内保存

通信が不安定な会場でも使えるよう、基本機能は端末内で完結する。

- データはブラウザの `localStorage` に保存
- 開発者、管理者、コーチの端末やサーバーへ自動送信しない
- サマリー画像も端末内で生成する
- `sw.js` により主要ファイルをキャッシュする

### 2.3 ルールベース分析

分析コメントはAI生成ではない。
決められた集計結果に対して、決められた条件でコメントを出す。
判定しきい値と表示件数は `ANALYSIS_COMMENT_RULES` で管理する。

メリット:

- 同じデータなら同じコメントになる
- オフラインで動作する
- 個人情報を外部送信しない
- コメントの根拠を説明しやすい
- 想定外の助言が出にくい

機能:

- ゲームごとの折りたたみ表示
- 日付表示

- 新規試合
- 試合情報を編集

- 保存済み試合
- バージョン情報
- 管理用
  - CSVを出力
- 閉じる

`閉じる`、`入力をリセット`、`開始/保存` はダイアログ下部に固定し、入力途中でも操作しやすくする。

## 6. データ構造

保存先は `localStorage`。キーは以下。

```js
soft-tennis-logger-state-v1
soft-tennis-logger-archive-v1
```

`soft-tennis-logger-state-v1` は現在編集中の試合を保存する。
`soft-tennis-logger-archive-v1` は新規試合前に自動保存された試合データを保存する。

### 6.1 state概要

```js
{
  matchType: "doubles" | "singles",
  teams: { A, B },
  players: { AFront, ARear, BFront, BRear },
  gamesToWin,
  matchFormat,
  matchInfo,
  server,
  selectedCourse,
  selectedOutcome,
  selectedResult,
  selectedServe,
  selectedHand,
  selectedPlayer,
  analysisMemos,
  points,
  gamePoints: { A, B },
  games: { A, B },
  finished
}
```

### 6.2 point概要

1ポイント記録するたび、`points` に1件追加する。

主な項目:

```js
{
  winner,
  server,
  serveStart,
  outcome,
  result,
  hand,
  player,
  shot,
  course,
  rally,
  phase,
  gameNumber,
  scoreBefore,
  scoreAfter,
  gameWonBy,
  memo,
  at
}
```

`scoreBefore` と `scoreAfter` を持つため、履歴表示や取り消しがしやすい。

## 8. 分析ロジック

### 8.1 基本集計

`getAnalysisData()` で以下を集計する。

- 総記録ポイント
- 自チーム得点
- 相手得点
- ポイント差
- ゲーム最初の1本
- 自チームの得点パターン数
- 相手ミスによる自チーム得点
- 自チームミスによる失点
- 第1サービスの本数/率
- 第2サービス開始数
- ダブルフォールト
- レシーブミス
- 最初の2本での失点
- 主な得点パターン
- 主な失点ミス
- 主なボール結果
- 主なプレイヤー

### 8.2 ゲーム最初の1本

各ゲームの最初のポイントを自チームが何本取れたかを集計する。

例:

- `3/5本`: 5ゲーム中3ゲームで最初の1本を取れている
- `0/3本`: 立ち上がりで相手に流れを渡している可能性がある

### 8.3 得点タイプ

自チーム得点のうち、得点パターンと相手ミス得点の割合で判定する。

- 得点パターンが60%以上: 攻撃型
- 相手ミス得点が60%以上: 相手ミス誘発型
- それ以外: バランス型

### 8.4 記録から分かること

`buildQuickCoachItems()` で生成する。

主な条件:

- ダブルフォールトがある
- レシーブミスがある
- 最初の2本での失点が多い
- 第1サービスの本数/率が低い
- 相手ミス得点が多い
- 主な得点パターンがある

試合中の短い確認を想定し、最大2件に絞る。

### 8.5 全体の傾向

`buildPriorityItems()` で生成する。

主な条件:

- 失点で最も多い内容
- 最初の2本での失点
- ゲームポイント付近やデュース以降の失点
- 相手の主なミス
- 相手サービス時のレシーブミス献上
- 相手に取り切られた点

文末の句点は付けず、箇条書き向きの表現にしている。

### 8.6 分析コメント

サマリー画像用に `buildSummaryComments()` で生成する。

AIが毎回考えるのではなく、ルールベースでコメントを出す。
判定しきい値と表示件数は `ANALYSIS_COMMENT_RULES` で管理する。

主な条件:

- ポイント差がプラス
- ポイント差がマイナス
- ポイント差がゼロ
- ゲーム最初の1本の取得数
- ミス失点が得点パターンを上回る
- 得点パターン率が60%以上
- 相手ミス得点率が60%以上
- ダブルフォールトまたはレシーブミスがある
- 最初の2本での失点が多い
- 主な得点パターンがある

コメント例:

- 合計ポイントは+3。ゲーム結果だけでなく内容でも押せている
- 合計ポイントは-2。ゲーム前半や簡単な失点を減らす余地がある
- ミス失点が得点パターンを上回る。まず失点を減らす
- 得点の60%が自チームの得点パターン。良い形を次の試合でも再現したい

## 9. 選手別 + / - とプレー内容

学生時代の紙記録に近い考え方を取り入れた項目。

集計ルール:

- 得点パターン: そのプレイヤーに `+1`
- ミス系: そのプレイヤーに `-1`
- 右端に差分を表示

例:

```text
自後衛 +3 / -1 / +2
```

不明、未設定、未記録のプレイヤーは集計対象外。

表示上は、ダブルスなら後衛・前衛の4人、シングルスなら自分・相手を常に表示する。
まだ得点・ミスがない選手は `+0 / -0 / ±0` として表示する。

## 10. サマリー画像

`canvas` でPNG画像を端末内生成する。

### 10.1 目的

詳細なCSVではなく、試合後に共有しやすい振り返り画像を作る。

### 10.2 現在の構成

Markdown記号は表示せず、見出し、区切り線、視覚的な点による箇条書きで、一般ユーザが読みやすい1枚画像として表示する。
用途に応じて `共有用` と `詳細保存用` を切り替えられる。

共有用:

- SNSやLINEで送りやすい短めの画像
- 基本情報、試合結果、分析コメント、次に活かすポイント、主な数字を中心に表示

詳細保存用:

- 後から見返すための情報多めの画像
- 共有用の内容に加えて、根拠データと試合条件を多めに表示

```text
ソフトテニス試合ノート

試合結果
分析コメント
次に活かすポイント
主な数字
基本情報
試合条件
```

基本情報には、チーム名だけでなくプレイヤー名も表示する。
ダブルスでは自チーム後衛、自チーム前衛、相手後衛、相手前衛を表示する。
シングルスでは自分、相手を表示する。

### 10.3 保存済み分析との関係

`この振り返りを保存` を押している場合、その時点の内容をサマリー画像に反映する。
保存していない場合は、現在の記録データから自動生成する。

### 10.4 共有

サマリー画像は、対応ブラウザではOS標準の共有メニューから各種SNSへ送れる。
別端末へ記録データを渡す場合は、CSVではなく引き継ぎ用データを保存してLINEなどで送る。
共有非対応ブラウザでは画像保存へ切り替える。

保存済み試合のサマリー画像は、保存済みの試合データから再生成する。
画像データそのものを大量に保存せず、試合データを残すことで保存容量を抑える。

## 12. セキュリティ・プライバシー

### 12.1 端末内保存

入力データは端末内のブラウザに保存する。
開発者、管理者、コーチの端末やサーバーには送られない。

### 12.2 CSP

`index.html` でContent Security Policyを設定している。

```html
default-src 'self';
script-src 'self';
style-src 'self';
img-src 'self' data:;
connect-src 'self';
object-src 'none';
base-uri 'none';
form-action 'self'
```

### 12.3 HTMLエスケープ

画面表示時は `escapeHtml()` を使って、入力値がHTMLとして実行されないようにする。

### 12.4 CSVエスケープ

CSV出力時は `escapeCsvCell()` を使い、CSV注入やカンマ・ダブルクォート崩れを避ける。

### 12.5 注意点

端末内保存のため、以下の場合はデータが見えなくなる可能性がある。

- ブラウザのサイトデータ削除
- プライベートブラウズ利用
- 端末故障
- ブラウザ変更
- 容量不足やOSの自動削除

重要データはサマリー画像またはCSVで別途保存する。

## 13. オフライン対応

`sw.js` で以下のファイルをキャッシュする。

```js
[
  "./",
  "index.html",
  "app-config.js",
  "app-analysis.js",
  "app-storage.js",
  "app-rules.js",
  "styles.css",
  "app.js",
  "manifest.webmanifest"
]
```

キャッシュ名はバージョンごとに更新する。
`index.html` の `app-config.js?v=数字`、`app-analysis.js?v=数字`、`app-storage.js?v=数字`、`app-rules.js?v=数字`、`app.js?v=数字`、`styles.css?v=数字`、`app-config.js` の `APP_VERSION`、`sw.js` の `CACHE_NAME` は同じ数字にそろえる。

サービスワーカー登録も `sw.js?v数字` 相当で行い、新しいサービスワーカーは `skipWaiting()` と `clients.claim()` で早めに有効化する。

```js
soft-tennis-logger-v208
```

## 15. 現在の制約

- 複数試合の本格的な過去管理は未実装
- データは端末ごとに独立している
- チーム共有・クラウド同期は未実装
- 分析コメントはルールベースで、AI生成ではない
- サマリー画像は固定サイズのCanvas出力
- CSVは詳細確認用で、一般ユーザー向けの見やすい画面ではない
- ブラウザや端末の保存仕様により、localStorageデータが消える可能性がある

## 17. 開発・運用方針

正本フォルダ:

```text
Documents/Apps/soft-tennis-note
```

基本運用:

1. PC内の正本を編集する
2. ローカルで確認する
3. テストを実行する
4. Gitにコミットする
5. `CHANGELOG.md` と必要な設計書を更新する
6. テスト環境へ反映して確認する
7. 問題なければ本番へPushする
8. GitHub Pages公開版を確認する

GitHub上で直接編集するとPC側の正本とズレやすいため、基本的にはPC側で編集してからGitHubへ反映する。
