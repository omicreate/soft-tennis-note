# 基本設計書・方式設計書

最終更新: 2026-05-28  
対象バージョン: v129

## 1. 全体方式

ソフトテニス試合ノートは、サーバーを持たない静的Webアプリとして構成する。

```text
スマホブラウザ
  ├─ index.html
  ├─ styles.css
  ├─ app.js
  ├─ sw.js
  └─ localStorage
```

サーバー側でデータを受け取らず、記録データは利用者の端末内に保存する。

## 2. 採用理由

### 2.1 静的Webアプリ

理由:

- GitHub Pagesで無料公開できる
- サーバー保守が不要
- 個人情報をサーバーに集めない
- スマホのSafari、Chromeで利用できる
- 将来PWA化しやすい

制約:

- 端末やブラウザを変えるとデータは引き継がれない
- ブラウザのサイトデータ削除で保存データが消える
- LINE内ブラウザなど一部環境では保存や共有が不安定になる場合がある

## 3. 画面構成

### 3.1 記録画面

1ポイント終了後に入力する画面。

役割:

- スコア確認
- サービス情報の入力
- 得点、失点内容の入力
- プレイヤー、到達位置、ラリー数などの詳細入力
- 得点した側の保存

設計方針:

- サービスは必ず最初に発生するため、入力上部に置く
- 得点パターンとミス/失点パターンを近くに置く
- 到達位置など迷いやすい項目は詳細記録として扱う
- 得点した側のボタンは最後に押す

### 3.2 分析画面

試合中と試合後の両方で使う画面。

役割:

- 今の試合の傾向を短く見る
- 試合後に詳しく振り返る
- 分析メモを保存する

設計方針:

- 試合中にすぐ見る項目を上に置く
- 詳細な根拠データは下に置く
- 分析コメントは断定しすぎず、事実から次の観点を出す

### 3.3 履歴画面

1ポイントごとの記録を確認する画面。

役割:

- 入力ミス確認
- 試合の流れ確認
- ゲームごとの振り返り

設計方針:

- ゲーム単位で折りたたむ
- フィルターで見たいポイントだけに絞る
- 色で自チーム得点と相手得点を区別する

### 3.4 メニュー

補助操作をまとめる。

主な機能:

- 新規試合
- 試合情報を編集
- サマリー画像を表示
- 今の試合を保存
- 保存済み試合
- バージョン情報
- 管理用CSV出力

## 4. データ保存方式

保存先:

```text
ブラウザ localStorage
```

主なキー:

```text
soft-tennis-logger-state-v1
soft-tennis-logger-archive-v1
```

保存方針:

- 現在の試合は常に端末内に保持する
- 新規試合作成前に記録済み試合を自動保存する
- ユーザーが `今の試合を保存` を押した場合も保存済み試合へ残す
- 画像そのものは大量保存せず、必要時に試合データから再生成する

## 5. オフライン方式

`sw.js` のService Workerで主要ファイルをキャッシュする。

対象:

- `index.html`
- `styles.css`
- `app.js`
- `manifest.webmanifest`

キャッシュ名はバージョンごとに変更する。

例:

```text
soft-tennis-logger-v129
```

`index.html` の読み込みバージョン、`app.js` の `APP_VERSION`、`sw.js` のキャッシュ名はそろえる。

## 6. セキュリティ方式

### 6.1 外部通信

アプリ本体は外部APIへ送信しない。

### 6.2 CSP

`index.html` にContent Security Policyを設定する。

目的:

- 外部スクリプト読み込みを避ける
- 予期しない外部送信を避ける
- HTMLに埋め込まれた危険なコードの実行リスクを下げる

### 6.3 入力値表示

ユーザー入力を画面に表示する場合は、HTMLとして解釈されないようエスケープする。

### 6.4 CSV

CSV出力時は、表計算ソフトで数式として実行される可能性がある文字列をエスケープする。

## 7. 公開方式

本番:

```text
https://omicreate.github.io/soft-tennis-note/
```

検証:

```text
https://omicreate.github.io/soft-tennis-note-preview/
```

運用:

- 本番用フォルダを正本にする
- 検証環境へ同期して確認する
- 問題なければ本番へPushする

## 8. バージョン管理方式

アプリ表示、読み込みファイル、Service Workerのキャッシュ名を同じ番号にそろえる。

確認対象:

- `index.html` の `styles.css?v=数字`
- `index.html` の `app.js?v=数字`
- `app.js` の `APP_VERSION`
- `sw.js` の `CACHE_NAME`
- `CHANGELOG.md`
- `TEST_REPORT.md`

保存データ形式を変える場合は、古いデータや一部項目が欠けたデータを読めるように正規化処理を残す。

## 9. 横展開を見据えた考え方

今後ピックルボールやテニスへ広げる場合、以下を分離して考える。

- 共通化しやすいもの
  - 試合作成
  - スコア表示
  - 履歴
  - サマリー画像
  - CSV出力
  - 端末内保存

- 競技別に変えるもの
  - スコアルール
  - 用語
  - 得点パターン
  - ミス分類
  - コート図
  - 分析コメント

現時点では単一アプリとして実装しているが、将来は競技別設定を切り出す余地がある。
