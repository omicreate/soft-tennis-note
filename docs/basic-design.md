# 基本設計書・方式設計書

最終更新: 2026-06-01  
対象バージョン: v211

## 1. 全体方式

ソフトテニス試合ノートは、サーバーを持たない静的Webアプリとして構成する。

```text
スマホブラウザ
  ├─ index.html
  ├─ app-config.js
  ├─ app-analysis.js
  ├─ app-storage.js
  ├─ app-rules.js
  ├─ styles.css
  ├─ app.js
  ├─ sw.js
  └─ localStorage
```

サーバー側でデータを受け取らず、記録データは利用者の端末内に保存する。

## 2. 採用理由

### 2.1 静的Webアプリ

理由:

- GitHub Pagesで無料公開できる
- サーバー保守が不要
- 個人情報をサーバーに集めない
- スマホのSafari、Chromeで利用できる
- 将来PWA化しやすい

制約:

- 端末やブラウザを変えるとデータは引き継がれない
- ブラウザのサイトデータ削除で保存データが消える
- LINE内ブラウザなど一部環境では保存や共有が不安定になる場合がある

## 3. 画面構成

### 3.1 記録画面

1ポイント終了後に入力する画面。

役割:

- スコア確認
- サービス情報の入力
- 得点、失点内容の入力
- プレイヤー、到達位置、ラリー数などの詳細入力
- 得点した側の保存

設計方針:

- サービスは必ず最初に発生するため、入力上部に置く
- 得点パターンとミス/失点パターンを近くに置く
- 到達位置など迷いやすい項目は、試合後に履歴から補足する詳細情報として扱う
- 得点した側のボタンは最後に押す

### 3.2 分析画面

試合中と試合後の両方で使う画面。

役割:

- 今の試合の傾向を短く見る
- 試合後に詳しく振り返る
- 分析メモを保存する

設計方針:

- 試合中にすぐ見る項目を上に置く
- 詳細な根拠データは下に置く
- 分析コメントは断定しすぎず、事実から次の観点を出す

### 3.3 履歴画面

1ポイントごとの記録を確認する画面。

役割:

- 入力ミス確認
- 試合の流れ確認
- ゲームごとの振り返り

設計方針:

- ゲーム単位で折りたたむ
- フィルターで見たいポイントだけに絞る
- 色で自チーム得点と相手得点を区別する

### 3.4 メニュー

補助操作をまとめる。

主な機能:

- 新規試合
- 試合情報を編集
- サマリー画像を見る
- 保存済み試合
- バージョン情報
- 管理用CSV出力

## 4. データ保存方式

保存先:

```text
ブラウザ localStorage
```

主なキー:

```text
soft-tennis-logger-state-v1
soft-tennis-logger-archive-v1
```

保存方針:

- 現在の試合は常に端末内に保持する
- 新規試合作成前に記録済み試合を自動保存する
- ポイント追加、取り消し、試合情報編集、分析メモ保存、履歴補足時に保存済み試合へ自動反映する
- 画像そのものは大量保存せず、必要時に試合データから再生成する

## 5. オフライン方式

`sw.js` のService Workerで主要ファイルをキャッシュする。

対象:

- `index.html`
- `app-config.js`
- `app-analysis.js`
- `app-storage.js`
- `app-rules.js`
- `styles.css`
- `app.js`
- `manifest.webmanifest`

キャッシュ名はバージョンごとに変更する。

例:

```text
soft-tennis-logger-v211
```

`index.html` の読み込みバージョン、`app-config.js` の `APP_VERSION`、`sw.js` のキャッシュ名はそろえる。
JavaScriptは `app-config.js`、`app-analysis.js`、`app-storage.js`、`app-rules.js`、`app.js` の順に読み込む。

## 6. 試合情報入力方式

試合情報ダイアログは、最低限の試合情報と追加項目に分ける。
最低限の項目は常時表示し、追加項目は `<details>` で折りたたむ。
ダイアログ内はスクロール可能にし、操作ボタンは下部固定で残す。
テキスト入力には `autocomplete=off` と `enterkeyhint` を設定し、スマホキーボード利用時の流れを補助する。

## 7. 記録モード切替方式

保護者や初回利用者の入力負担を下げるため、初期表示はかんたん記録モードにする。
詳細な記録が必要な場合は、同じ記録画面内で詳細モードへ切り替える。
プレイヤー選択、サーブした人、レシーブした人はかんたん記録でも表示し、個人別 `+ / -` とサーブ/レシーブ傾向の記録を保つ。
画面切替はCSSクラスで制御し、保存形式は同じ `state.points` を使う。

## 8. サーブ/レシーブ選手入力方式

記録画面では、サービスサイドに応じてサーブ選手、反対側をレシーブ選手として選択できる。
未選択でも記録できるよう `不明` を用意し、入力負担を抑える。かんたん記録でも表示するが、ボタン数を抑えたコンパクトな選択UIにする。
保存データには `serverPlayer`、`receiverPlayer` を追加し、履歴、CSV、分析、サマリーで同じ値を参照する。

## 9. サマリー画像方式

サマリー画像はCanvasで複数ページ相当の縦長PNGとして生成する。
1枚の画像内でページ番号を表示し、共有用と詳細保存用で情報量を切り替える。
各ページは、試合結果、分析コメント、図解、個人別、試合条件のように役割を分ける。

## 10. セキュリティ方式

### 10.1 外部通信

アプリ本体は外部APIへ送信しない。

### 10.2 CSP

`index.html` にContent Security Policyを設定する。

目的:

- 外部スクリプト読み込みを避ける
- 予期しない外部送信を避ける
- HTMLに埋め込まれた危険なコードの実行リスクを下げる

### 9.3 入力値表示

ユーザー入力を画面に表示する場合は、HTMLとして解釈されないようエスケープする。

### 9.4 CSV

CSV出力時は、表計算ソフトで数式として実行される可能性がある文字列をエスケープする。

- 問題なければ本番へPushする

## 8. バージョン管理方式

アプリ表示、読み込みファイル、Service Workerのキャッシュ名を同じ番号にそろえる。

確認対象:

- `index.html` の `styles.css?v=数字`
- `index.html` の `app.js?v=数字`
- `index.html` の `app-config.js?v=数字`
- `app-config.js` の `APP_VERSION`
- `sw.js` の `CACHE_NAME`
- `CHANGELOG.md`
- `TEST_REPORT.md`

保存データ形式を変える場合は、古いデータや一部項目が欠けたデータを読めるように正規化処理を残す。

## 9. 横展開を見据えた考え方

今後ピックルボールやテニスへ広げる場合、以下を分離して考える。

- 共通化しやすいもの
  - 試合作成
  - スコア表示
  - 履歴
  - サマリー画像
  - CSV出力
  - 端末内保存

- 競技別に変えるもの
  - スコアルール
  - 用語
  - 得点パターン
  - ミス分類
  - コート図
  - 分析コメント

現時点では単一アプリとして実装しているが、将来は競技別設定を切り出す余地がある。
