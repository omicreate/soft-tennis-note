## 1. 結論

現時点では、テストユーザーへ無料公開してフィードバックを受ける段階としてリリース可能。

理由:

- スコア進行、保存、分析、履歴、サマリー画像、CSV、引き継ぎ用データの主要機能が動作している
- スマホ幅のE2E確認を実施している
- 端末内保存、CSP、CSV注入対策、HTMLエスケープを入れている
- 利用条件、プライバシー、セキュリティ文書を整備した

## 2. 今すぐ大きく書き換えないもの

### `app.js` の本格分割

分割した方がよいが、最終リリース直前には大きく触らない。

理由:

- `app.js` は大きいが、現在の自動テストと実機確認で動作が安定している
- UI、状態更新、サマリー、CSV、履歴の依存が強く、急な分割は副作用が大きい
- テストユーザー公開後のフィードバック対応速度を優先する

次に分ける候補:

1. `app-summary.js`
   - サマリー画像生成、Canvas描画
   - 理由: `app.js` 内で大きく、UI本体から独立しやすい

2. `app-csv.js`
   - CSVヘッダー、行生成、ファイル名、エスケープ
   - 理由: 仕様が固定されており、テストしやすい

3. `app-ui-render.js`
   - 記録、分析、履歴、保存済み試合の描画関数
   - 理由: 量は多いが、副作用が大きいため段階的に行う

4. `app-state.js`
   - `state` の正規化、初期化、保存同期
   - 理由: 将来の団体戦、複数試合比較、他スポーツ展開で重要

## 3. 動作を変えずに整理した方がよいもの

優先度順:

1. サマリー画像生成の分離
   - 理由: 画像ページ数、文字量、SNS共有などの変更が今後も増える

2. CSV処理の分離
   - 理由: 管理用データとして仕様固定しやすく、セキュリティ確認もしやすい

3. 分析表示用データの中間形式化
   - 理由: 画面、サマリー、CSVで同じ分析結果を使いやすくする

4. UI文言の設定ファイル化
   - 理由: 中学生、保護者、コーチ向けに文言調整が続く

5. テストfixtureの追加
   - 理由: 実運用フィードバックで出た試合パターンを再現しやすくする

## 4. セキュリティ・脆弱性

現時点の確認:

- `npm audit --audit-level=moderate`: 0 vulnerabilities
- CSP設定あり
- 外部API送信なし
- CSV注入対策あり
- HTMLエスケープあり
- 個人CSVを `.gitignore` で除外

残課題:

- 実機Safari、LINE内ブラウザ、Android標準ブラウザの継続確認
- 共有画像に個人名を出しすぎない運用説明
- AI機能追加時の外部送信・費用・同意設計

## 5. 法令・権利

現時点の対応:

- `TERMS.md` に利用条件を記載
- `PRIVACY.md` に端末内保存、外部送信なし、削除方法を記載
- `SECURITY.md` に脆弱性連絡、公開禁止データを記載
- `LICENSE.md` にオープンソースライセンスではないことを記載
- `package.json` は `UNLICENSED`、`private: true`

注意:

- GitHub Publicリポジトリでは、GitHubの機能として閲覧やforkは可能
- ただし、明示ライセンスを付けないため、一般的な再配布・改変利用・商用利用は許可しない
- 完全にコード閲覧を防ぎたい場合は、GitHub PagesのPublic公開では限界がある
