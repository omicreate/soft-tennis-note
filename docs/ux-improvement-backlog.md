# ユーザビリティ改善候補

最終更新: 2026-06-01

## 1. 方針

このアプリは、試合中にすべてを細かく入力することを目的にしない。

優先すること:

- 試合中に迷わず記録できる
- 親や学生が、最低限でも個人別の `+ / -` を残せる
- コーチや管理者は、あとから詳細CSVや保存済み試合を確認できる
- サマリーは、次の練習や次の試合に活かせる言葉と数字を先に見せる

## 2. 優先度高

### 2.1 かんたん入力（v156で初期改善済み、v157で何が起きたかの視認性を改善）

目的:

- 親や学生が迷わず使える入口にする

入力するもの:

- サービス
- サーブした人、レシーブした人
- 誰のプレーか
- 得点かミスか
- 得点側

理由:

- 子供たちは個人別の `+ / -` に興味が強い
- 親は細かい戦術用語より、誰がどう得点・失点したかを残したい
- 記録が続かなければ分析も育たない

### 2.2 詳細記録を後から追加できる形（v156で履歴補足を追加）

目的:

- 試合中に入力しきれなかった内容を、履歴から試合後に補えるようにする

対象:

- コース
- 到達位置
- 打球面
- フォア/バック
- ラリー数
- メモ

理由:

- 試合中はポイント間が短く、詳細入力を画面上に出すだけでも継続率が落ちる可能性がある
- DFやレシーブミスでは到達位置の判断が難しい
- フォア/バックまで試合中に取れるのは、テニス理解がありスマホ操作に慣れた記録者に限られる

### 2.3 サマリーの見せ方を「次に活かす」順に寄せる（v156で初期改善済み）

表示順:

1. 試合結果
2. プレイヤー別 `+ / -` とプレー内容
3. サーブ/レシーブの成功・ミス傾向
4. 1ポイント目取得率
5. 連続得点・連続失点
6. ゲームポイント/マッチポイントの取り切り
7. 分析コメント
8. 詳細データ

理由:

- 子供と保護者が一緒に見た時、最初に納得しやすい
- コーチは後半の詳細データを使って練習テーマに落とせる

## 3. 優先度中

### 3.1 試合中画面と試合後画面の分離

試合中:

- 記録しやすさ優先
- ボタン数を減らす
- スコアと次の入力を大きくする

試合後:

- 詳細分析
- サマリー画像
- 保存済み試合
- 管理用CSV

理由:

- 試合中と試合後では利用目的が違う
- 同じ画面に全部入れると、親や学生には難しく見える

### 3.2 初回だけの練習データ

目的:

- 初めて触る人が、いきなり本番試合で迷わないようにする

内容:

- サンプル試合を1つ読み込む
- 記録、分析、サマリーの流れを触れる

理由:

- 説明文を読むより、触った方が早い

## 4. 優先度低

### 4.1 AIコメント

将来的には有効だが、現時点では優先度を下げる。

理由:

- API費用、個人情報、利用規約、責任範囲を整理する必要がある
- まずはルールベース分析の精度を上げる方が現実的

### 4.2 団体戦対応

個人戦で記録・分析の形が固まってから着手する。

理由:

- 入力項目と保存構造が増える
- 先に個人戦の使いやすさを固めた方が横展開しやすい
