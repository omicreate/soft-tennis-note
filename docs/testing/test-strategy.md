# テスト実行パターン

最終更新: 2026-06-02
対象バージョン: v206

## 目的

開発のたびに毎回すべてを確認すると、時間も会話コンテキストも消費しやすい。
今後は変更内容に応じて、軽量チェック、画面チェック、フルチェックを使い分ける。

## 実行パターン

| パターン | コマンド | 使うタイミング | 主な確認 |
| --- | --- | --- | --- |
| 軽量チェック | `npm run test:quick` | 文言、CSS、小さな分析表示変更 | 構文、主要分析、HTML/CSS静的確認 |
| 画面チェック | `npm run test:visual` | レイアウト、ボタン、サマリー画像表示変更 | スマホ幅、横はみ出し、主要画面表示 |
| データ回帰 | `npm run test:fixtures` | CSV、分析集計、サンプルデータ変更 | 実データ由来の期待値との一致 |
| 単体一式 | `npm run test:unit` | ロジック変更、保存仕様変更 | スコア、分析、保存、CSV、静的確認 |
| フル確認 | `npm run test:full` | 検証環境反映前、本番反映前 | 単体一式 + E2E全体 |

## 運用ルール

- UIだけの小修正は、まず `test:quick`、必要に応じて `test:visual`
- スコア、保存、分析、CSVに触れたら `test:unit`
- サマリー画像、スマホ表示、ダイアログに触れたら `test:visual`
- 検証環境へ push する前は、原則 `test:quick` または該当パターンを実行
- 本番反映前は `test:full` を実行
- 実機でしか分からない内容は `device-test-results.md` に残す

## コンテキスト節約の考え方

- 失敗したテストだけ重点的にログを見る
- 毎回すべてのコードを読み直さず、変更範囲と関連テストを先に確認する
- 画面崩れは Playwright のスクリーンショットと横はみ出し検査を優先する
- 仕様変更があった時だけ設計書を更新し、単なる文言変更は `CHANGELOG.md` と `TEST_REPORT.md` を中心に残す
