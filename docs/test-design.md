# テスト設計書

最終更新: 2026-05-28  
対象バージョン: v144

## 1. テスト方針

富士通SDEMのように、工程ごとに確認すべき観点を分ける考え方を参考にする。

このアプリでは、個人開発として現実的な範囲で以下を確認する。

- ルール通りにスコアが進むこと
- 入力した内容が分析、履歴、サマリー、CSVに正しく反映されること
- スマートフォンで見切れや操作しにくさがないこと
- 保存データが想定通り端末内に残ること
- 古いキャッシュが残りにくいこと
- 異常な入力や壊れた保存データでアプリが壊れないこと

実際の結果は `../TEST_REPORT.md` に残す。

## 2. テスト分類

| 分類 | 内容 |
| --- | --- |
| 単体テスト | スコア計算、分析集計など関数単位の確認 |
| 結合テスト | 記録、履歴、分析、保存がつながっているか確認 |
| 画面テスト | スマホ表示、文字切れ、ボタン配置の確認 |
| 回帰テスト | 以前直した不具合が再発していないか確認 |
| 異常系テスト | 不正データ、空入力、壊れた保存データの確認 |
| リリース確認 | 検証環境、本番環境、バージョン、キャッシュの確認 |

## 3. 重要テスト観点

### 3.1 スコア進行

- 5ゲームマッチで3ゲーム先取になる
- 7ゲームマッチで4ゲーム先取になる
- 9ゲームマッチで5ゲーム先取になる
- ファイナルゲームのみで1ゲーム終了になる
- 通常ゲームは4ポイント先取、2ポイント差になる
- ファイナルゲームは7ポイント先取、2ポイント差になる
- デュース時もポイント数が表示される
- ファイナルゲーム中は2ポイントごとにサービス側が交替する
- 試合終了後に追加得点できない
- 前のポイントに戻した時、スコア、履歴、分析が戻る

### 3.2 記録データ

- サービス側が保存される
- 第1サービス、第2サービス、ダブルフォールトが保存される
- 得点パターンが保存される
- ミス/失点パターンが保存される
- プレイヤーが保存される
- 到達位置、ボールの結果、ショット、打球面、ラリー数、メモが保存される
- 保存後に次の入力がしやすい位置へ戻る

### 3.3 分析

- 相手ミスが自チーム失点として集計されない
- 自チームミスが相手得点、ミス失点として集計される
- 自チーム得点パターンが正しく集計される
- 相手ミスパターンが見える
- 個人別 `+ / -` に全選手が表示される
- 未記録選手は `+0 / -0 / ±0` で表示される
- 0件の棒グラフが進んで見えない

### 3.4 履歴

- ゲームごとに区切られる
- 自チーム得点と相手得点が色分けされる
- フィルターが正しく効く
- 新しい順、古い順が切り替わる
- 日付が表示される

### 3.5 サマリー画像

- チーム名が入る
- 全プレイヤー名が入る
- 試合結果が分かる
- 分析コメントが入る
- 次に活かすことが入る
- 根拠データが入る
- スマホ画面で保存、共有ボタンが見切れない
- ファイル名が重複しにくい
- 共有非対応時に保存へ切り替わる

### 3.6 保存

- `今の試合を保存` で保存済み試合に残る
- 新規試合前に自動保存される
- 保存済み試合を開き直せる
- サマリー画像を再生成できる
- ブラウザを閉じても同じ端末、同じブラウザなら残る

### 3.7 試合情報

- 新規試合作成時に開始時刻が自動入力される
- 試合終了時に終了時刻が自動入力される
- 開始時刻、終了時刻を後から編集できる
- 入力リセットで初期値へ戻る
- 閉じる、入力をリセット、開始/保存ボタンが下部に固定される

### 3.8 セキュリティ

- HTML表示時に入力値がエスケープされる
- CSV出力時に数式注入対策がされる
- 外部スクリプトを読み込まない
- 入力データを外部送信しない

## 4. 異常系テスト

| 観点 | 期待結果 |
| --- | --- |
| localStorageのJSONが壊れている | 初期状態に戻り、画面が壊れない |
| チーム名が空 | 既定値にフォールバックする |
| 不正な得点側 | スコア、履歴が変わらない |
| 不正な試合形式 | 既定の7ゲーム相当にフォールバックする |
| 画像共有非対応 | 画像保存案内へ切り替わる |
| 空履歴で取り消し | エラーにならない |
| 形式が違う試合データファイル | 復元せずエラー扱いにする |

## 5. リリース前チェック

実行コマンド:

```sh
node --check app-config.js
node --check app-analysis.js
node --check app-storage.js
node --check app-rules.js
node --check app.js
node --check sw.js
node tests/analysis-counts.test.js
node tests/match-flow.test.js
node tests/responsive-static.test.js
npm run test:e2e
```

確認項目:

- 検証環境でGitHub Pagesが成功している
- 検証URLで最新バージョンが表示される
- 本番環境でGitHub Pagesが成功している
- 本番URLで最新バージョンが表示される
- `app.js?v=数字` と `styles.css?v=数字` が最新
- Service Workerのキャッシュ名が最新
- スマホで古い表示が出る場合はキャッシュ再読み込みを案内する

## 6. Playwright E2Eテスト

`tests/e2e/mobile-layout.spec.js` で、スマホ相当の画面幅を確認する。

確認する主な画面:

- 記録画面
- 分析画面
- 履歴画面
- 保存済み試合ダイアログ
- サマリー画像ダイアログ

確認する主な内容:

- 主要UIが表示される
- 横方向にはみ出さない
- 保存済み試合の検索、日付/種目/状態/勝敗/大会の絞り込み、並び替え、件数表示、容量目安が存在する
- サマリー画像の共有用、詳細保存用、共有、保存ボタンが見える
- サマリー画像は、試合結果、分析コメント、次に活かすことを先に表示する
- 試合データ読込で、ファイル選択から現在の試合と保存済み試合が復元される
- 長い試合データでもサマリー画像画面のボタンがスマホ幅に収まる
- サマリー画像の本文がフッター領域に重ならない
- 実機確認結果は `device-test-results.md` に端末・ブラウザ別で残す
