# テスト設計書

最終更新: 2026-06-02
対象バージョン: v209

## 1. テスト方針

富士通SDEMのように、工程ごとに確認すべき観点を分ける考え方を参考にする。

このアプリでは、個人開発として現実的な範囲で以下を確認する。

- ルール通りにスコアが進むこと
- 入力した内容が分析、履歴、サマリー、CSVに正しく反映されること
- スマートフォンで見切れや操作しにくさがないこと
- 保存データが想定通り端末内に残ること
- 古いキャッシュが残りにくいこと
- 異常な入力や壊れた保存データでアプリが壊れないこと

実際の結果は `../TEST_REPORT.md` に残す。

## 2. テスト分類

| 分類 | 内容 |
| --- | --- |
| 単体テスト | スコア計算、分析集計など関数単位の確認 |
| 結合テスト | 記録、履歴、分析、保存がつながっているか確認 |
| 画面テスト | スマホ表示、文字切れ、ボタン配置の確認 |
| 回帰テスト | 以前直した不具合が再発していないか確認 |
| 異常系テスト | 不正データ、空入力、壊れた保存データの確認 |
| リリース確認 | 検証環境、本番環境、バージョン、キャッシュの確認 |

## 3. 重要テスト観点

### 3.1 スコア進行

- 5ゲームマッチで3ゲーム先取になる
- 7ゲームマッチで4ゲーム先取になる
- 9ゲームマッチで5ゲーム先取になる
- ファイナルゲームのみで1ゲーム終了になる
- 通常ゲームは4ポイント先取、2ポイント差になる
- ファイナルゲームは7ポイント先取、2ポイント差になる
- デュース時もポイント数が表示される
- ファイナルゲーム中は2ポイントごとにサービス側が交替する
- 試合終了後に追加得点できない
- 前のポイントに戻した時、スコア、履歴、分析が戻る

### 3.2 記録データ

- サービス側が保存される
- 第1サービス、第2サービス、ダブルフォールトが保存される
- 得点パターンが保存される
- ミス/失点パターンが保存される
- プレイヤーが保存される
- 到達位置、ボールの結果、ショット、打球面、ラリー数、メモが保存される
- 保存後に次の入力がしやすい位置へ戻る

### 3.3 分析

- 相手ミスが自チーム失点として集計されない
- 自チームミスが相手得点、ミス失点として集計される
- 自チーム得点パターンが正しく集計される
- 相手ミスパターンが見える
- 選手別 `+ / -` に全選手が表示され、記録したプレー内容と記録から分かることも確認できる
- かんたん記録でサーブした人、レシーブした人、レシーブミスを入力できる
- 個人別S/Rがカード形式で見切れず表示され、個人別コメントの根拠にも使われる
- 未記録選手は `+0 / -0 / ±0` で表示される
- 0件の棒グラフが進んで見えない

### 3.4 履歴

- ゲームごとに区切られる
- 自チーム得点と相手得点が色分けされる
- フィルターが正しく効く
- 新しい順、古い順が切り替わる
- 日付が表示される

### 3.5 サマリー画像

- チーム名が入る
- 全プレイヤー名が入る
- 試合結果が分かる
- 分析コメントが入る
- 次に活かすポイントが入る
- 根拠データが入る
- スマホ画面で保存、共有ボタンが見切れない
- ファイル名が重複しにくい
- 共有非対応時に保存へ切り替わる
- 端末引き継ぎメニューから、試合データを保存・読み込みできる

### 3.6 保存

- ポイント記録時に保存済み試合へ自動保存される
- 新規試合前に自動保存される
- 保存済み試合を開き直せる
- サマリー画像を再生成できる
- ブラウザを閉じても同じ端末、同じブラウザなら残る

### 3.7 試合情報

- 新規試合作成時に開始時刻が自動入力される
- 試合終了時に終了時刻が自動入力される
- 開始時刻、終了時刻を後から編集できる
- 入力リセットで初期値へ戻る
- 閉じる、入力をリセット、開始/保存ボタンが下部に固定される

### 3.8 セキュリティ

- HTML表示時に入力値がエスケープされる
- CSV出力時に数式注入対策がされる
- 保存済み試合一括CSVで、ポイントあり試合とポイントなし試合を同じファイルへ出力できる
- 外部スクリプトを読み込まない
- 入力データを外部送信しない

## 4. 異常系テスト

| 観点 | 期待結果 |
| --- | --- |
| localStorageのJSONが壊れている | 初期状態に戻り、画面が壊れない |
| チーム名が空 | 既定値にフォールバックする |
| 不正な得点側 | スコア、履歴が変わらない |
| 不正な試合形式 | 既定の7ゲーム相当にフォールバックする |
| 画像共有非対応 | 画像保存案内へ切り替わる |
| 空履歴で取り消し | エラーにならない |
| 形式が違う試合データファイル | 復元せずエラー扱いにする |

## 5. テスト実行パターン

詳しい使い分けは `testing/test-strategy.md` に残す。

| パターン | コマンド | 用途 |

## 6. リリース前チェック

実行コマンド:

```sh
npm run test:full
```

確認項目:

- 検証環境でGitHub Pagesが成功している
- 検証URLで最新バージョンが表示される
- 本番環境でGitHub Pagesが成功している
- 本番URLで最新バージョンが表示される
- `app.js?v=数字` と `styles.css?v=数字` が最新
- Service Workerのキャッシュ名が最新
- スマホで古い表示が出る場合はキャッシュ再読み込みを案内する

## 7. Playwright E2Eテスト

`tests/e2e/mobile-layout.spec.js` で、スマホ相当の画面幅を確認する。

確認する主な画面:

- 記録画面
- 分析画面
- 履歴画面
- 保存済み試合ダイアログ
- サマリー画像ダイアログ

確認する主な内容:

- 主要UIが表示される
- 横方向にはみ出さない
- 保存済み試合の検索、日付/種目/状態/勝敗/大会の絞り込み、並び替え、件数表示、容量目安が存在する
- サマリー画像の共有用、詳細保存用、共有、保存ボタンが見える
- サマリー画像は、試合結果、分析コメント、得点/失点図解、個人別、次に活かすポイントをページ単位で表示する
- 試合データ読込で、ファイル選択から現在の試合と保存済み試合が復元される
- 長い試合データでもサマリー画像画面のボタンがスマホ幅に収まる
- サマリー画像の本文がフッター領域に重ならない
- 実機確認結果は `device-test-results.md` に端末・ブラウザ別で残す

## 8. 実運用CSV fixture

実運用CSVを匿名化したfixtureを `tests/fixtures/` に置き、CSV出力列、集計値、選手別 `+ / -`、ゲームの1ポイント目、連続得点を単体テストで確認する。
fixture分析回帰テストでは、CSVをアプリ内部データへ変換し、分析指標とサマリー画像用データが期待値からズレていないか確認する。追加fixture群でも、ポイント数、ゲーム最初の1本、ゲームスコア、連続得点/失点、選手別 `+ / -` 表示を確認する。
元CSVに含まれる個人名に近い情報はGit管理しない。


## 9. UX改善回帰

### 9.1 かんたん入力

確認すること:

- 初期表示がかんたん入力である
- サービス側、サービス結果、選手、何が起きたか、得点側の順に記録できる
- DFをかんたん入力から選択できる
- 試合中の記録画面では詳細入力モードを出さず、到達位置や打球面などは履歴から後で補足できる

### 9.2 ポイント詳細の後補足

確認すること:

- 履歴の各ポイントから「詳細を補足」を開ける
- 誰のプレー、ポイント内容、到達位置、ラリー数、メモを更新できる
- 補足後の内容が履歴、分析、サマリー、CSVに反映される
- スコア、得点側、ゲーム取得は補足画面では変更されない

### 9.3 サマリー表示順

確認すること:

- 共有用サマリーは、試合結果、選手別 + / -、流れと勝負所、サーブ/レシーブ、次に活かす内容の順で表示される
- 詳細保存用サマリーは6ページ構成で、文字がフッターやボタンに重ならない


- 分析画面は `全体分析 / 個人別分析` を切り替えられる。全体分析は試合全体の流れ、得点・失点傾向、ラリー長さ、勝負どころを数字中心で見る。個人別分析は選手ごとの `+ / -`、関与したプレー、サーブ/レシーブ、記録コメントを見る。


- 従来の標準/詳細切替は廃止し、詳細分析の内容を用途別に再配置する。
- 全体デザインは部活ノート寄りの背景・カード表現を採用し、青=自チーム、赤=相手の意味は維持する。


- 個人別分析では、全選手の `+ / -`、関与本数、主な得点/ミスを表示する。後衛・前衛の良し悪しは決めつけず、記録された事実として扱う。


- 振り返り用サマリー画像にも `選手別の関わり` を表示し、全選手分の関与コメントを保持する。


- 親・コーチ・控え選手が記録し、選手へ見せながら振り返る利用を想定する。全体分析は数字確認、個人別分析は選手への提示とコメント保存に使う。
- アプリ全体は、部活ノートを共有するような柔らかいカード・紙面調の見た目にする。


- サマリー画像は、共有用・振り返り用の両方で、文字と枠・アクセント線が近づきすぎていないこと、保存画像としてスマホ上で読み取れることを確認する。
