# 技術レビュー・改善バックログ

最終更新: 2026-05-28  
対象バージョン: v129

個人開発者として、現状を忖度なしで見た改善メモ。  
今すぐ全部やるものではなく、テスト運用の反応を見ながら優先度を調整する。

## 対応済み

### P1 保存データの正規化強化

対応:

- `localStorage` の保存データが一部欠けていても、既定値へフォールバックするよう改善
- `teams`, `players`, `matchInfo`, `games`, `gamePoints`, `points`, `analysisMemos` を正規化

理由:

- テスト運用中にバージョンアップを重ねるため、古い保存データや中途半端な保存データを読めることが重要

### P2 CSVファイル名改善

対応:

- CSVファイル名に年月日・時分秒・チーム名を含める

理由:

- 同じ日に複数回出力した時の重複確認を減らす
- 後から見た時に、どの試合データか分かりやすくする

### P2 サマリー共有キャンセル時の挙動改善

対応:

- 共有画面でキャンセルしただけの場合は、画像保存へ自動で切り替えない
- ブラウザ非対応や共有失敗時のみ保存へ切り替える

理由:

- ユーザーがキャンセルしただけなのに、別操作が始まると混乱するため

## 未対応・今後対応候補

### P1 `app.js` の分割

現状:

- `app.js` が約2,100行
- スコア、分析、保存、サマリー、UI処理が1ファイルに集まっている

リスク:

- 今後の修正で副作用が出やすい
- ピックルボール、テニス、団体戦へ横展開しにくい
- 分析ロジックだけをテストしづらい

対応案:

- `score`、`analysis`、`storage`、`summary`、`ui` の単位で分ける
- ただし現在は静的HTML構成のため、分割時は読み込み方式も含めて慎重に行う

### P1 分析ルールの設定化

現状:

- 分析コメントやしきい値がコード内に直接書かれている

リスク:

- 文言調整のたびにコード修正が必要
- 他競技へ横展開する時に流用しづらい

対応案:

- 得点パターン、ミス分類、分析コメント、しきい値を設定データ化する
- 競技ごとの設定を切り替えられる形にする

### P2 UI自動テスト

現状:

- スコア、分析のロジックテストはある
- スマホ画面の見切れ、文字切れ、ボタン配置は手動確認中心

対応案:

- PlaywrightでiPhone/Android相当の画面幅を自動撮影
- 記録、分析、履歴、メニュー、サマリー画像の主要画面を確認する

### P2 サマリー画像の用途分離

現状:

- SNS共有向けの1枚画像として固定サイズで出力

リスク:

- 試合内容が多い場合、一部情報が省略される

対応案:

- SNS共有用の短い画像
- 詳細保存用のロング画像
- 2種類に分ける

### P3 保存済み試合の管理強化

一部対応済み:

- 保存済み試合の検索
- 保存済み試合の件数表示
- 保存済み試合の削除

残課題:

- 保存件数と容量の目安表示
- 日付や相手名での並び替え

### P3 利用規約・プライバシー文書の強化

現状:

- `TERMS.md` はあるが、正式サービスや有料化には不足

対応案:

- プライバシーポリシー
- 問い合わせ先
- データ削除方法
- AI機能利用時の外部送信説明
