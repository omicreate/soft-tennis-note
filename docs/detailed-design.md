# 詳細設計書

最終更新: 2026-05-28  
対象バージョン: v142

| ファイル | 役割 |

| `index.html` | 画面構造 |
| `app-config.js` | バージョン、保存キー、初期状態、分析コメント設定 |

## 2. 状態管理

アプリの中心データは `state`。
初期値は `app-config.js` の `defaultState` で管理し、`app.js` 側では読み込んだ設定を使って状態を正規化する。

概要:

```js
{
  matchType,
  teams,
  players,
  gamesToWin,
  matchFormat,
  matchInfo,
  server,
  selectedCourse,
  selectedOutcome,
  selectedResult,
  selectedServe,
  selectedHand,
  selectedPlayer,
  analysisMemos,
  points,
  gamePoints,
  games,
  finished
}
```

設計意図:

- 画面表示は基本的に `state` から再描画する
- 1ポイントの記録は `points` に追加する
- 取り消し時は `points` を元にスコアを再構築できるようにする
- 保存、サマリー、CSVも同じ `state` を元に作る

保存データ読込時は `normalizeState()` で正規化する。

主な方針:

- `teams`, `players`, `matchInfo` は既定値とマージする
- `games`, `gamePoints` は `A/B` の数値へ補正する
- `points`, `analysisMemos` が配列でない場合は空配列へ戻す
- 旧名称の用語は現在の分類へ寄せる

## 3. 試合情報

`matchInfo` に試合条件を保存する。

主な項目:

- 日付
- 時間帯
- 開始時刻
- 終了時刻
- 天気
- 気温
- 風
- コート種別
- コート状態
- 区分
- 大会名
- 開催地、会場
- コート
- 相手の基本布陣

開始時刻は新規試合作成時に自動設定する。  
終了時刻は試合終了時に自動設定する。  
どちらも試合情報編集から修正できる。

## 4. ポイントデータ

1ポイントごとに `points` へ保存する。

概要:

```js
{
  winner,
  server,
  serveStart,
  outcome,
  result,
  hand,
  player,
  shot,
  course,
  rally,
  phase,
  gameNumber,
  scoreBefore,
  scoreAfter,
  gameWonBy,
  memo,
  at
}
```

主な考え方:

- `winner` はポイントを取った側
- `outcome` は得点パターンやミス分類
- `player` は誰のプレーか
- `scoreBefore` と `scoreAfter` を持たせ、履歴表示と取り消しを分かりやすくする
- `gameWonBy` がある場合、そのポイントでゲームを取ったことを表す

## 5. スコア計算

### 5.1 通常ゲーム

- 4ポイント先取
- 2ポイント差
- デュース以降も内部ポイント数で管理する

### 5.2 ファイナルゲーム

- 7ポイント先取
- 2ポイント差
- 2ポイントごとにサービス側を交替する

### 5.3 マッチ終了

必要ゲーム数に到達したら `finished = true` にする。

必要ゲーム数:

| 形式 | 必要ゲーム数 |
| --- | ---: |
| 5ゲーム | 3 |
| 7ゲーム | 4 |
| 9ゲーム | 5 |
| ファイナルゲームのみ | 1 |

## 6. 記録処理

基本の流れ:

1. 記録画面で入力値を選ぶ
2. 得点した側を押す
3. その時点のスコアを `scoreBefore` に残す
4. ポイントを加算する
5. ゲーム取得、試合終了を判定する
6. `scoreAfter` を残す
7. `points` に追加する
8. localStorageへ保存する
9. 画面を再描画する
10. 次の入力位置へスクロールする

## 7. 取り消し処理

最後のポイントを削除し、残った `points` からスコアを再構築する。

設計意図:

- スコアだけを逆算しない
- 履歴、分析、保存データも同じ結果になるようにする
- 試合終了後でも前のポイントに戻せるようにする

## 8. 分析処理

中心関数:

```text
getAnalysisData()
SOFT_TENNIS_ANALYSIS.buildQuickCoachItemsFromData()
buildPriorityItems()
SOFT_TENNIS_ANALYSIS.buildSummaryCommentsFromData()
```

### 8.1 getAnalysisData

全ポイントから集計する。

主な集計:

- 総ポイント
- 自チーム得点
- 相手得点
- ポイント差
- 自チーム得点パターン
- 相手ミス得点
- 自チームミス失点
- 第1サービス開始率
- ダブルフォールト
- レシーブミス
- 最初の2本での失点
- 個人別 `+ / -`

### 8.2 buildQuickCoachItems

試合中に短く確認する項目を作る。

例:

- ダブルフォールトがある
- レシーブミスがある
- 最初の2本で失点が多い
- 第1サービス開始率が低い

### 8.3 buildPriorityItems

試合後に確認したい項目を作る。

例:

- 失点で最も多い内容
- 相手の主なミス
- ゲーム終盤の失点
- 相手サービス時のレシーブミス

### 8.4 buildSummaryComments

サマリー画像に載せる分析コメントを作る。

AI生成ではなく、集計結果に対するルールベース。

同じデータなら基本的に同じコメントになる。

判定しきい値と表示件数は `ANALYSIS_COMMENT_RULES` に集約する。
表示文言は `ANALYSIS_COMMENT_MESSAGES` に集約し、`app-analysis.js` で差し込み値を反映する。
主な設定:

- 攻撃型判定: 得点パターン率60%以上
- 相手ミス誘発型判定: 相手ミス得点率60%以上
- 第1サービス低確率判定: 60%未満
- 最初の2本での失点注意: 3本以上
- 試合中メモ: 最大2件
- あとで確認すること: 最大4件
- サマリーコメント: 最大5件

## 9. 個人別 + / -

紙記録の考え方を取り入れた集計。

ルール:

- 得点パターンは対象プレイヤーに `+1`
- ミス系は対象プレイヤーに `-1`
- 差分を `±` で表示する
- ダブルスは後衛、前衛の4人を常に表示する
- シングルスは自分、相手を表示する

注意:

- `不明` は個人別集計の主対象にしない
- プレイヤー名が未入力でも、役割名で表示できるようにする

## 10. サマリー画像

CanvasでPNG画像を生成する。

構成:

- 基本情報
- 試合結果
- 分析コメント
- 次に活かすこと
- 根拠データ
- 試合条件

画像は2種類に分ける。

- 共有用: SNSやLINEで送りやすい短めの画像
- 詳細保存用: 後で見返すため、根拠データと試合条件を多めに含める画像

描画後は本文末尾とフッター開始位置を返し、単体テストで文字がフッター領域に重ならないことを確認する。

保存ファイル名は重複しにくいよう、用途、日時、チーム名を含める。

例:

```text
soft-tennis-summary-share-20260528153010-team-vs-opponent.png
soft-tennis-summary-detail-20260528153010-team-vs-opponent.png
```

## 11. CSV出力

CSVは管理者、開発者、詳細確認向け。

方針:

- 一般利用者向けのメイン機能にはしない
- メニュー内の管理用に置く
- すべてのポイント詳細を出力する
- CSV注入対策を行う
- ファイル名には年月日・時分秒・チーム名を含める

## 12. 保存済み試合

保存条件:

- `今の試合を保存` を押した時
- 新規試合作成前に記録済み試合がある時

保存内容:

- 試合情報
- チーム名
- プレイヤー名
- スコア
- 全ポイント履歴
- 分析メモ

保存しないもの:

- サマリー画像のPNGデータ本体
- 外部サーバー上のデータ

管理機能:

- 保存済み試合の件数を表示する
- 保存件数と端末内で使っている容量の目安を表示する
- 日付、相手名、大会名、会場、プレイヤー名で検索できる
- 日付、種目、終了/途中、勝敗、大会名で絞り込みできる
- 新しい順、古い順、名前順で並び替えできる
- 不要な保存済み試合を確認付きで削除できる

保存済み試合の読み書きと容量表示は `app-storage.js` の `SOFT_TENNIS_STORAGE` に分離する。

## 13. エラー、例外対応

想定している主な異常:

- 壊れたlocalStorage
- 空のチーム名
- 不正な試合形式
- 不正な得点側
- 試合終了後の追加得点
- 画像共有非対応ブラウザ
- 形式が違う試合データファイル

基本方針:

- 可能な場合は初期値へフォールバックする
- スコアや履歴を壊さない
- 非対応機能は代替操作に切り替える

## 14. 試合データ保存・読込

管理用メニューから、現在の試合と保存済み試合をまとめて保存できる。  
利用者向け画面では `JSON` という技術用語を出さず、`試合データを保存`、`試合データを読み込む` と表示する。  
内部形式はJSONとする。

含める情報:

- アプリ識別子
- スキーマバージョン
- アプリバージョン
- 出力時刻
- 現在の試合データ
- 保存済み試合データ

復元時は確認を挟み、現在の試合と保存済み試合をバックアップ内容で置き換える。  
別アプリや形式が違うファイルは復元しない。
